# Сервис согласования макетов

Консольное приложение для согласования дизайн-макетов между
дизайнером и клиентом: учёт макетов, комментариев клиента,
статусов, версий и сроков согласования.

## Назначение

Приложение решает задачу упорядочивания процесса приёмки работы:
дизайнер отправляет макет на согласование с указанием срока, клиент
оставляет комментарии и принимает решение — утвердить макет или
отправить на доработку. Все замечания, версии и статусы хранятся в
одном месте, что исключает потерю правок в почте и мессенджерах.

## Целевая аудитория

- дизайнеры и дизайн-студии, сдающие макеты заказчику;
- клиенты (заказчики), принимающие работу и оставляющие замечания;
- менеджеры проектов, контролирующие сроки согласования.

## Предметная область

Дизайнер создаёт макет и отправляет его клиенту на согласование,
указывая срок ответа. Клиент оставляет к макету комментарии и
переводит макет в один из статусов: «На согласовании», «На доработке»
или «Утверждён». При отправке на доработку версия макета
увеличивается, и цикл повторяется до утверждения. Утверждённый макет
повторно не утверждается и не отправляется на доработку.

## Основные классы

### Participant — участник согласования

Базовый класс для дизайнера и клиента.

Атрибуты: `id` — идентификатор; `name` — имя; `email` — почта.

Методы: `role` — свойство с названием роли; `from_data()` — создание
объекта из данных JSON; `to_data()` — преобразование в данные для
сохранения; `__str__()` — строковое представление.

### Designer — дизайнер

Наследник `Participant`, автор макета. Переопределяет свойство
`role`, поэтому один и тот же вызов `str()` для дизайнера и клиента
даёт разный результат.

### Client — клиент

Наследник `Participant`, заказчик, согласующий макет.

Дополнительный атрибут: `company` — организация клиента.
Переопределены `role`, `from_data()`, `to_data()` и `__str__()`;
`to_data()` вызывает реализацию базового класса через `super()`.

### Layout — макет

Объект согласования. Хранит ссылки на объекты `Designer` и `Client`.

Атрибуты класса: `STATUS_REVIEW`, `STATUS_REVISION`,
`STATUS_APPROVED` — возможные статусы, общие для всех макетов.

Атрибуты объекта: `id`, `title`, `designer`, `client`, `sent_date`,
`approval_days`, `version`, `_status`.

Методы: `status` — свойство, доступ к статусу только для чтения;
`deadline` — свойство, срок согласования рассчитывается из даты
отправки; `is_approved` — свойство-признак утверждения;
`days_left()` — число дней до окончания срока; `approve()` —
утверждение макета; `send_to_revision()` — отправка на доработку с
увеличением версии; `from_data()`, `to_data()`, `__str__()`.

### Comment — комментарий

Замечание клиента к конкретной версии макета. Хранит ссылки на
объекты `Layout` и `Client`.

Атрибуты: `id`, `layout`, `author`, `text`, `date`,
`layout_version`.

Методы: `is_valid_text()` — статический метод проверки текста;
`from_data()`, `to_data()`, `__str__()`.

## Взаимодействие объектов

    Designer ──┐
               ├──> Layout <──── Comment ────> Client (автор)
    Client ────┘

Макет связывает дизайнера и клиента: `layout.designer.name`,
`layout.client.company`. Комментарий связан с макетом и его автором:
`comment.layout.title`, `comment.author.name`. Связи между объектами
хранятся в оперативной памяти как ссылки, а в JSON-файлах — как
идентификаторы (`designer_id`, `client_id`, `layout_id`,
`author_id`).

## Возможности

- просмотр списка макетов с сортировкой по сроку согласования;
- поиск макета по части названия;
- регистрация макета на согласование с расчётом срока ответа;
- просмотр и добавление комментариев клиента к макету;
- отправка макета на доработку с созданием новой версии;
- утверждение макета;
- статистика по статусам макетов и количеству комментариев;
- просмотр списка дизайнеров и клиентов;
- сохранение данных в JSON-файлах между запусками программы.

## Назначение модулей

- `main.py` — точка входа: меню, ввод данных, пользовательские
  сценарии;
- `models/participants.py` — классы `Participant`, `Designer`,
  `Client` и функции работы с их коллекциями;
- `models/layouts.py` — класс `Layout` и функции обработки коллекции
  макетов (поиск, фильтрация, сортировка, статистика);
- `models/comments.py` — класс `Comment` и функции работы с
  комментариями;
- `models/__init__.py` — импорт классов из пакета `models`;
- `storage.py` — загрузка и сохранение данных: JSON → объекты и
  объекты → JSON;
- `utils.py` — безопасный ввод строк, чисел и дат;
- `tests/` — автоматизированные тесты проекта.

## Хранение данных

Данные хранятся в каталоге `data/` в формате JSON. При загрузке
записи преобразуются в объекты `Designer`, `Client`, `Layout` и
`Comment`, при сохранении объекты преобразуются обратно в данные.

`data/layouts.json`:

    {
        "id": 1,
        "title": "Главная страница интернет-магазина",
        "version": 2,
        "designer_id": 1,
        "client_id": 1,
        "sent_date": "2026-09-10",
        "approval_days": 5,
        "status": "На доработке"
    }

`data/comments.json`:

    {
        "id": 1,
        "layout_id": 1,
        "author_id": 1,
        "text": "Увеличить логотип",
        "date": "2026-09-13",
        "layout_version": 1
    }

## Требования

- Python 3.x;
- pytest;
- flake8.

Установка зависимостей:

    pip install -r requirements.txt

## Запуск программы

    python main.py

## Тестирование

    pytest -v

Тесты проверяют создание объектов `Designer`, `Client`, `Layout` и
`Comment`, значения их атрибутов, строковые представления, различие
ролей при наследовании, расчёт срока согласования, утверждение макета
и запрет повторного утверждения, увеличение версии при доработке,
поиск, фильтрацию, сортировку и статистику, а также связь комментария
с макетом и его автором.
